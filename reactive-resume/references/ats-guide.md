# ATS 优化指南

## ATS 是怎么工作的

申请人追踪系统（ATS）先于 HR 的眼睛看到你的简历。它的典型流程：

1. **解析**：把你的文件拆成结构化字段（姓名、联系方式、每段经历的起止时间、技能）。
2. **打分**：按 JD 关键词匹配度排序，匹配度低的简历 HR 根本看不到。
3. **存储**：解析失败的简历（乱码、表格错位）会被标为"待人工"，实际上等于沉底。

结论：**ATS 友好的本质是"机器读得顺"**。人觉得好看的设计（双栏、图标、色块）常常是机器的灾难。

## 格式红线（每条都有代价）

| 红线 | 原因 |
|---|---|
| 不用表格排版 | 多数 ATS 解析表格会错位或串行 |
| 不用分栏承载核心信息 | 阅读顺序可能被解析乱 |
| 不用图片/图标承载文字 | 纯视觉，ATS 完全读不到 |
| 不用页眉页脚放关键信息 | 很多解析器跳过页眉页脚 |
| 不用特殊字体 | 用系统标准字体（思源黑体/宋体/Arial） |
| 日期格式统一 | 全篇 `YYYY-MM` 或全篇 `YYYY年MM月`，别混用 |
| 联系方式纯文本 | 别放成超链接样式或图片 |
| 避免"技能进度条" | 进度条本质是图形，写文字熟练度 |

## 关键词策略

1. 通读 JD，把**硬技能词**（Python、SQL、项目管理、用户增长……）和**软素质词**（跨团队协作、Owner 意识）各列一单。
2. 每个硬技能词必须在简历里**字面出现**至少一次——同义词不算（JD 写 CRM，你写"客户关系管理"，ATS 不认）。
3. 词从哪里进：技能区块、摘要、经历 bullet。三处呼应，密度自然。
4. 缩写和全称都写：`CRM（客户关系管理）`。
5. **不造假**：没做过的技能不要硬塞。塞进去面试被追问，代价更大。

## 文件格式

- **PDF 最稳**：由 Markdown/Word 导出，别用图片型 PDF（扫描件 ATS 读不了）。
- **DOCX 次选**：部分老系统偏好。
- 文件名：`姓名-职位-工作年限.pdf`，例：`张三-市场经理-6年.pdf`。
- 投递前用 `validate_resume.py ats` 扫一遍。

## 交付前检查清单

- [ ] 姓名、手机、邮箱在正文顶部，纯文本，格式正确
- [ ] 全篇日期格式统一（`YYYY-MM`）
- [ ] 无表格、无分栏排版、无图标文字、无页眉页脚关键信息
- [ ] 标准字体，字号 ≥ 9pt
- [ ] JD 硬技能词全部字面出现
- [ ] 每条经历 bullet 都有动作 + 结果，多数带数字
- [ ] 篇幅：10 年内经验控制在 1–2 页，每页信息密度充足
- [ ] 导出为 PDF（非扫描件），文件名规范

## 常见误区

- **"设计越好看录取率越高"**：机器关和人都要过，第一关是机器。
- **"关键词堆得越多越好"**：堆到正文不通顺会同时惹恼机器（判定作弊）和人（读不下去）。
- **"一页定生死"**：10 年经验硬压一页会丢关键证据；重点是每页都有信息量，而非绝对页数。
